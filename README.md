# session.py — Session Memory Injector

A command-line tool for developers who use AI assistants (Claude, Gemini, ChatGPT, etc.) across multiple sessions and are tired of re-explaining the same context every time.

**The problem:** AI chat windows have no memory between sessions. Every time you start fresh, you waste the first chunk of the conversation catching the AI back up — what the project does, what was fixed last time, what's in progress. Get far enough into a large project and this becomes genuinely painful.

**The solution:** `session.py` watches your project files, diffs what changed each session, asks a local LLM to summarize the changes in plain English, and builds a running memory log. At the start of any new session, one command gives you a clean paste-ready briefing to drop straight into the chat window.

Everything runs locally. Nothing leaves your machine.

---

## Requirements

- Python 3.6+
- [Ollama](https://ollama.com) with at least one model installed

Ollama is a free tool for running AI models locally. If you don't have it:

```bash
# Install from https://ollama.com, then pull a model:
ollama pull qwen2:1.5b    # small and fast, good for summarizing
ollama pull llama3.2      # larger, better quality
```

## Installation

```bash
# Download session.py and put it somewhere on your PATH
cp session.py ~/bin/session.py
chmod +x ~/bin/session.py
```

That's it. No pip install, no dependencies beyond Python's standard library and Ollama.

## Quick Start

```bash
# 1. Create a project
session.py -n ~/Projects/MyProject

# 2. Add the directory you're working in
session.py -ap ~/Projects/MyProject ~/code/my-app

# 3. Snapshot before you start working
session.py -s ~/Projects/MyProject

# --- do your coding ---

# 4. End the session when done
session.py -x ~/Projects/MyProject

# 5. Next session — get a paste-ready briefing
session.py -b ~/Projects/MyProject
```

Paste the output of `-b` into any AI chat window and you're caught up in seconds.

## All Commands

### Project Setup

```bash
session.py -n  <project>              # Create a new project (interactive setup)
session.py -ap <project> <dir>        # Add a watched directory
session.py -af <project> <file>       # Add a specific watched file
session.py -lp <project>              # List all watched paths
session.py -rp <project> <path>       # Remove a watched path
```

### Exclude Patterns

```bash
session.py -xe <project> <pattern>    # Add a per-project exclude pattern (e.g. "*.log")
session.py -le <project>              # List all active exclude patterns
session.py -re <project> <pattern>    # Remove a per-project exclude pattern
```

### Session Workflow

```bash
session.py -s  <project>              # Start session — snapshot current state
session.py -x  <project>              # End session — diff, summarize, update memory
session.py -b  <project>              # Print paste-ready briefing for next AI session
```

### Documentation Audit

```bash
session.py -a  <project>              # Audit all .py files in watched paths
session.py -a  <project> <dir>        # Audit a specific directory (top level)
session.py -a  <project> <file.py>    # Audit a specific file
```

### Other

```bash
session.py -h                         # Show help
```

## How It Works

**Project files** are stored in the project folder you create with `-n`:

```
~/Projects/MyProject/
    session.json        ← config (name, model, watch list, excludes)
    session_memory.md   ← running memory log, human-readable markdown
    snapshots/          ← before/after snapshots (JSON, auto-managed)
    audit_report.md     ← generated by -a if you choose to save it
```

**`session.json` is never hand-edited** — all changes go through the script commands. If you're dyslexic or just hate editing JSON by hand, that's the point.

**The session cycle:**

1. `-s` takes a snapshot of all watched files (hashes + text content for text files)
2. You write code
3. `-x` takes another snapshot, diffs the two, sends the actual line-by-line changes to your local LLM, gets back a plain-English summary, and appends it to `session_memory.md`
4. `-b` reads `session_memory.md` and formats it for pasting

**The diff is real** — not just "this file changed." The LLM sees the actual unified diff so it can say "added error handling to the webhook function" rather than "amy_ledger.py was modified."

## Exclude Patterns

Some files are always skipped regardless of project:

| Pattern | Reason |
|---|---|
| `.*` | Hidden files |
| `*.swp`, `*.swo` | Vim swap files |
| `*.bak`, `*backup*`, `*~` | Backup files |
| `venv/`, `.venv/` | Python virtual environments |
| `__pycache__/` | Python bytecode cache |
| `.git/`, `node_modules/` | Version control and package dirs |

Add your own per-project patterns with `-xe`:

```bash
session.py -xe ~/Projects/MyProject "*.log"
session.py -xe ~/Projects/MyProject "temp_*"
```

If you explicitly add a file with `-af` that matches an exclude pattern, it will still be tracked — the override warning tells you, but respects your choice.

## Documentation Audit

The `-a` command sends your Python files to the local LLM and asks it to flag:

- Functions or classes with no docstring
- Variables with no inline comment explaining what they hold
- Global variables not clearly marked as globals

```bash
# Audit everything in the watch list
session.py -a ~/Projects/MyProject

# Audit a specific file
session.py -a ~/Projects/MyProject ~/code/my-app/main.py
```

Large files are automatically split at function boundaries and audited in chunks. At the end you're asked whether to save the results to `audit_report.md`.

**Note:** A small model like `qwen2:1.5b` is good at finding issues but not at writing fixes. Use the audit report as a checklist and fix the issues in your normal AI coding session with a more capable model.

## Choosing a Model

When you create a project with `-n`, the script detects your installed Ollama models and lets you pick. You can have different projects use different models.

For summarizing session changes, a small model works fine:
- `qwen2:1.5b` — fast, 934MB, good enough

For documentation audit, a slightly larger model gives better results:
- `llama3.2` — 2GB, noticeably better at reading code intent
- `llama3` — 4.7GB, best quality if you have the RAM

## Philosophy

This tool is intentionally simple. It doesn't integrate with your editor, doesn't run as a daemon, doesn't require a database. It's a script you run at the start and end of a work session, same as clocking in and out.

The architecture mirrors the project that spawned it — the [Amy AGI project](https://bicameralmind.space) — where a subconscious layer preprocesses information before it reaches the conscious mind. This script is the external subconscious for the developer: quietly tracking what changed so you don't have to remember it yourself.
